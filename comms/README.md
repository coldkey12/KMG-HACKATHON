# comms — канал сообщений между агентами A и B

Агенты работают на разных компьютерах и видят друг друга только через git. Здесь — короткие адресные сообщения:
запросы, ответы, блокеры, отчёты «готово». Каждое сообщение — отдельный файл в `comms/messages/`, поэтому
одновременная запись двух агентов не даёт конфликтов в git.

`docs/HANDOFF.md` остаётся для долгоживущего описания (контракт, где что лежит). Всё, что требует ответа или действия, — сюда.

## В начале каждого рабочего захода

```bash
git pull
python comms/msg.py inbox A      # агент A;  агент B — inbox B
```

Открытые сообщения — первое, что разбирает агент: ответить (`reply`), сделать и закрыть (`reply --close` или `close`).

## Команды

```bash
python comms/msg.py send --from B --to A --type request --title "Коротко, что нужно" --body "Подробности" --refs lat-v.n-090-6c1318
python comms/msg.py reply <id> --from A --body "Сделано в c404f88" --close
python comms/msg.py close <id> --by A --note "не требуется: ..."
python comms/msg.py show <id>    # сообщение и ответы на него
python comms/msg.py log          # последние сообщения
```

`<id>` можно сокращать до начала имени файла.

| Поле | Значения |
|---|---|
| `from`, `to` | `A`, `B`, `human-A` (Владимир), `human-B` (Темирлан), `all` |
| `type` | `request` — нужно действие; `blocker` — без этого стою; `answer` — ответ; `fyi` — к сведению; `done_report` — готово, можно забирать; `question_geologist` — вопрос геологу через человека |
| `status` | `open` (ждёт адресата) → `done`; `info` — не требует действия |

## Правила

1. Закрывает сообщение только адресат.
2. Одно сообщение — одна просьба. Указывай id узлов/утверждений/файлов в `--refs` и коммит, где сделано.
3. Секреты (ключи) в сообщения не писать. Материалы хакатона не цитировать длиннее, чем нужно для дела.
4. Изменение контракта слоя по-прежнему записывается в `docs/CONTRACT_CHANGELOG.md`; сюда — уведомление о нём.
5. Сообщение доходит до другой стороны только после `commit` + `push`. Агент коммитит сообщение сразу;
   пушит — по правилу команды (по просьбе своего человека).
6. `question_geologist` — человек пересылает геологу и пишет ответ через `reply`.
