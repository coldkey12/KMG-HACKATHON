# Контракт учебного слоя — v0.1.0 (временный)

Схема: [`layer.schema.json`](layer.schema.json) (JSON Schema 2020-12). Владелец — агент A. Изменения — только через
[`docs/CONTRACT_CHANGELOG.md`](../docs/CONTRACT_CHANGELOG.md); запросы B — туда же.

Схемы организаторов у команды нет, поэтому поля взяты из перечня ТЗ («Задание и пакет сдачи», п. 1). Ключи
английские, но каждый соответствует формулировке ТЗ (таблица ниже) — перевод в официальную схему, если она
появится, будет отдельным преобразованием.

## Как устроен файл слоя

`out/<глава>/layer.json`:

| Ключ | Что |
|---|---|
| `chapter` | книга, глава, страницы PDF, язык, доменный пакет, `scope` (`full` / `sample`) |
| `units[]` | единицы главы (нарезка без модели): `id`, `kind`, `page`, `text`, `author_text`, `label` («Рис. 69», «Таблица 21», «Пример 46», «Задача 92»). Таблицы книги целиком лежат здесь, в `text` (markdown). `figure_description` — машинное описание рисунка из md, **не автор** |
| `parts[]` | части пути курса |
| `nodes[]` | узлы, порядок — поле `order` |
| `coverage[]` | таблица покрытия: каждая единица → узлы или причина, почему нет |
| `typos[]` | лист опечаток распознавания (исправления не делаются молча) |
| `open_questions[]` | вопросы геологу; утверждения с вопросом имеют `status: disputed` |
| `checks`, `metrics` | итог проверок и стоимость прогона |

## Происхождение текста

Каждое текстовое поле узла — объект `Txt`: `{text, by, claims[], hypothesis}`.

- `by`: `author` (дословно автор), `model` (написала модель), `rule` (детерминированное правило), `human` (ручная правка — с записью в журнале).
- `claims`: id утверждений узла, на которые опирается текст. По ним курс ставит «стр. N» и показывает цитату.
- `hypothesis: true` — не следует прямо из главы (ИТ-аналогия, «как сейчас», догадки о данных). **Курс обязан показывать такие места с пометкой «гипотеза»; в ролик они не идут как факт.**

Утверждение (`claims[]` узла): `text` (простыми словами), `kind` (observation/inference/assumption = наблюдение/вывод/допущение),
`page`, `quote` (дословная подстрока единицы `unit_id`), `status` (`ok` / `unverified` / `disputed`). **В ролик и в ключи заданий
идут только `status: ok`.**

## Соответствие полям ТЗ

| Поле ТЗ | Ключ |
|---|---|
| узлы в порядке, нужном неспециалисту | `nodes[].order` |
| обоснование «почему этот узел раньше» | `order_rationale` |
| полнота по единицам, таблица покрытия | `units[]`, `coverage[]` |
| разобранные примеры автора (условие, шаги, итог с числами автора) | `worked_examples[]` |
| задачи книги (номер, формулировка, какой рисунок нужен) | `book_problems[]` |
| слои «механизм → практика → нюансы» | `layers.mechanism / practice / nuances` |
| ветки «глубже» | `deeper[]` |
| тип трудности (основной и второй) | `difficulty.primary / secondary` (коды — `domain/<pack>/difficulty_types.yaml`) |
| утверждения с пометкой наблюдение/вывод/допущение, страницей и цитатой | `claims[]` |
| пометка на каждом поле, написано ли оно моделью | `by` в каждом `Txt` |
| связи с другими узлами с типом (предпосылка, пример, опровергает заблуждение, переход к данным) | `links[]`: `prerequisite / example / refutes_misconception / to_data` |
| заблуждение, которое узел исправляет | `misconception` (`pack_id` — id из списка ТЗ, `domain/<pack>/misconceptions.yaml`) |
| что это значит для данных и что здесь ломается | `data_meaning.inputs / outputs / breaks` |
| ИТ-аналогия и где она ломается | `it_analogy.analogy / breaks_where` |
| нюанс «как это делается сейчас» | `now_nuance` |
| метка пороговой идеи | `threshold.is_threshold` |
| линза неэффективности (входные данные, ручные шаги, точки суждения, время, типичные ошибки) | `inefficiency.inputs / manual_steps / judgment_points / time / typical_errors` |
| устойчивые идентификаторы | `nodes[].id`, `claims[].id`, `units[].id` |
| маршрутизация форматов с обоснованием | `format.format` (`short / long_video / interactive / data_practicum / cards / text`), `format.rationale`, `format.videoability` |
| шаблон сцены для видеоёмкого узла | `format.scene_template` (или «нужен новый»), `format.state_model` |
| «решение на данных» | `format.data_decision` |

## Блоки страницы шага ← поля узла

| Блок курса (ТЗ) | Откуда |
|---|---|
| Заголовок для новичка; полное название из книги | `title_novice`; `title_book` |
| Суть (2–3 фразы) | `summary[]` |
| Как это работает | `layers.mechanism` + `practice` + `nuances` |
| По шагам | `procedure[]` |
| Разбор примеров | `worked_examples[]` |
| Цифры и условия | `numbers_conditions[]` |
| Новые понятия | `terms_defined[]` (+ термины-предпосылки из `domain/<pack>/glossary.yaml`, `prerequisite: true`) |
| Формулы | `formulas[]` (исправленный LaTeX, переменные с единицами) |
| Таблицы книги | `tables[].unit_ids` → `units[].text`; правки — `typos[]` |
| Частая ошибка | `misconception` |
| Что это значит для данных | `data_meaning` |
| Аналогия | `it_analogy` |
| Источник | `claims[]`: `page`, `quote` |
| Задачи из книги | `book_problems[]` |
| Иллюстрации | `figures[]` (`redraw: true` — перерисовать кодом по скану, подпись «перерисовано по рис. N, стр. M») |

## Устойчивость идентификаторов

- `units[].id = u-<стр>-<hash6 нормализованного текста>`: правка в другой единице его не меняет.
- `nodes[].id = <глава>.n-<id первой опорной единицы без u->`.
- `claims[].id = <узел>.c-<hash6 цитаты>`.
- Повторный прогон без изменений берётся из кэша модели (`cache/llm/`), поэтому даёт тот же слой байт в байт.

## Проверки

`python -m kmg check out/<глава>/layer.json` — без модели: контракт, покрытие, цитаты на странице, числа в исходной единице,
порядок терминов. Отчёт — `out/<глава>/checks.md`. Проверка текста курса агентом B — см. `docs/HANDOFF.md`.
