# kmg_course — агент B: «учебный слой → демо-курс»

Одна команда собирает курс по главе из `layer.json` (контракт — `contract/`):

```bash
.venv/Scripts/python -m kmg_course build out/<глава>/layer.json      # → out/<глава>/course/
.venv/Scripts/python -m kmg_course build out/<глава>/layer.json --no-tasks   # без модели, $0
.venv/Scripts/python -m kmg_course build out/<глава>/layer.json --assets-only   # только приложение и оформление из доменного пакета (фото, легенда); содержание и задания не трогает, модель не вызывает
```

Курс открывается без сервера: `out/<глава>/course/index.html` (двойной щелчок). Код выхода 0 — курс собран,
заданий ≥15 и ≥4 типов, `tasks.json` проходит `task.schema.json` организаторов, `illustrations.json` — `illustration.schema.json`
(`docs/organizers/pack/01_схемы/`), у каждого шага есть иллюстрация, размер без видео ≤30 МБ. Иначе код 1 и сообщение
«ОШИБКА СБОРКИ КУРСА: …» в stderr. Итог — `course/course_report.json`.

Выход: `index.html`, `assets/` (приложение, фото из доменного пакета), `data/course.js` (модель курса),
`tasks.json` (формат организаторов), `illustrations.json` (формат организаторов) + `illus/*.svg`, `media/` (ролики и сцены).

## Что внутри

| Файл | Что |
|---|---|
| `model.py` | слой → модель курса: блоки страницы шага в порядке таблицы ТЗ; у каждого абзаца — страницы, цитаты, кто написал (`by`), гипотеза |
| `illus.py` | иллюстрации шага кодом из данных шага (метка «схема» на картинке); легенда цветов пород, флюидов и кривых, названных в шаге, — цвета и названия из стайлгайда доменного пакета (`domain/<пакет>/styleguide_official.json`, иначе `styleguide.yaml`); фото обложек из `domain/<пакет>/photos/photos.json` (класс D, источник и лицензия в подписи); генерации нет |
| `tasks.py` + `prompts/tasks.md` | задания: модель предлагает, код проверяет ключи без модели (утверждения узла со `status: ok`, совпадение с текстом шага, пересчёт расчётных, проверка текста агента A `check_course_items`); не прошедшие — в отчёт, не правятся вручную; прошедшие пишутся в формате `task.schema.json` и проверяются по схеме |
| `llm.py`, `models.yaml` | вызовы модели через кэш и учёт денег агента A; манифест моделей B |
| `static/` | приложение курса: путь, страница шага, задания, карточки, конспект с печатью в PDF, карта связей; без сети |

Повторная сборка без изменений слоя берёт задания из `cache/llm/` и стоит $0. Журнал вызовов — `runs/<глава>/course_llm_calls.jsonl`.

## Ролики и сцены

```bash
.venv/Scripts/python -m kmg_course video out/<глава>/layer.json <node_id> --format short|long [--template <id>] [--new-script]
.venv/Scripts/python -m kmg_course coverage out/*/layer.json      # реестр scenes/registry.json + отчёт покрытия по главам
.venv/Scripts/python -m kmg_course preview out/<глава>/layer.json <node_id> [--format short|long] [--template <id>]   # кадры всех частей сцены без сценария и голоса, $0
```

Шаблон узла выбирается так: шаблон роутера агента A (`format.scene_template`), если его правило применимости
выполняется для узла, иначе первый реализованный шаблон, чьё правило выполняется; тот же выбор делает отчёт покрытия.
Правила — данные в `templates/<id>.json` («applies»: тип трудности, признаки видеоёмкости, таблица признаков,
`terms` — сколько проверенных утверждений узла должны говорить о механизме, `not_terms` — о каком механизме говорить
нельзя, потому что сцена его не рисует). `preview` пишет `NN_<часть>.png`, тексты «что видно» для сценария и
проверку инвариантов в `preview.json` — шаблон проверяется на узле до того, как платить за сценарий.

`video` → `out/<глава>/media/<узел>/`: `*_short.mp4` (9:16) или `*_long.mp4` (16:9), `scene.html` (интерактив той же сцены
для курса), `voice.mp3`, `subtitles.srt/.vtt`, `passport.md/.json`, `spec.json`, `timeline.json`, `script.json`.
Следующая сборка курса (`build`) ставит ролик и интерактив на шаг узла.

Конвейер: спецификация сцены из шаблона (`video/templates/<id>.json` + `.js`) → сценарий (модель, роль `script`) →
проверки без модели (каждая фраза частей reveal/explain/data → утверждения узла `status: ok`; фраза ≤18 слов; без формул и
греческих букв; on_screen ≤7 слов; объём под формат; текст не противоречит вычисленной сцене; проверка текста агента A) →
голос (онлайн-голоса Microsoft, повторы, кэш `cache/tts/`, один голос на серию, запасной путь) → таймлайн по меткам слов →
инварианты сцены (чек-лист физики) до рендера → кадры той же страницы в Edge → FFmpeg (−16 LUFS) → паспорт.

Принятый сценарий хранится в `script.json` и переиспользуется, пока не меняются утверждения узла: правка факта в слое →
та же команда пересобирает сценарий, голос и ролик; правка шаблона → только перерисовка.

| Шаблон | Класс кадров | Модель состояния |
|---|---|---|
| `pressure_diffusion` | B | D(x,t) = erfc(x / 2√(κt)) — решение уравнения пьезопроводности: заливка пласта, профиль, граница зоны ∝ √t, датчик |
| `log_panel_decision` | A | синтетическая скважина из таблицы признаков книги: уровни ячеек → кривые; неразличимые по первой кривой пласты и различающие кривые вычисляются |
| `radial_profile` | B | два пласта (вода / нефть) у скважины; сопротивления зон по формуле Арчи, показание зонда — среднее зоны проникновения и пласта с весом J = 1 − exp(−глубина/глубинность); направление проникновения и влияние глубокого проникновения вычисляются. Отношение фильтрат/вода и глубина проникновения выбираются по тексту узла |
| `cutoff_transfer` | B | синтетические интервалы испытаний вокруг связи «кривая → свойство», наименьшие квадраты; критическое значение свойства → граничное значение кривой → разметка пластов «коллектор / неколлектор»; сдвиг порога пересчитывает число коллекторов |
