# kmg_course — агент B: «учебный слой → демо-курс»

Одна команда собирает курс по главе из `layer.json` (контракт — `contract/`):

```bash
.venv/Scripts/python -m kmg_course build out/<глава>/layer.json      # → out/<глава>/course/
.venv/Scripts/python -m kmg_course build out/<глава>/layer.json --no-tasks   # без модели, $0
.venv/Scripts/python -m kmg_course build out/<глава>/layer.json --assets-only   # только приложение и оформление из доменного пакета (фото, легенда); содержание и задания не трогает, модель не вызывает
.venv/Scripts/python -m kmg_course build out/<глава>/layer.json --reuse-tasks   # быстрая пересборка после правки факта (~1 с, без модели): страница из нового слоя; задания неизменённых узлов из прошлой сборки перепроверяются, задания узлов с изменёнными утверждениями снимаются до обычной сборки (course_report.json → changed_nodes_tasks_dropped)
```

Курс открывается без сервера: `out/<глава>/course/index.html` (двойной щелчок). Код выхода 0 — курс собран,
заданий ≥15 и ≥4 типов, `tasks.json` проходит `task.schema.json` организаторов, `illustrations.json` — `illustration.schema.json`
(`docs/organizers/pack/01_схемы/`), у каждого шага есть иллюстрация, размер без видео ≤30 МБ. Иначе код 1 и сообщение
«ОШИБКА СБОРКИ КУРСА: …» в stderr. Итог — `course/course_report.json`.

Выход: `index.html`, `assets/` (приложение, фото из доменного пакета), `data/course.js` (модель курса),
`tasks.json` (формат организаторов), `illustrations.json` (формат организаторов) + `illus/*.svg`, `media/` (ролики и сцены).

## Что внутри

| Файл | Что |
|---|---|
| `model.py` | слой → модель курса: блоки страницы шага в порядке таблицы ТЗ; у каждого абзаца — страницы, цитаты, кто написал (`by`), гипотеза |
| `illus.py` | иллюстрации шага кодом из данных шага (метка «схема» на картинке); легенда цветов пород, флюидов и кривых, названных в шаге, — цвета и названия из стайлгайда доменного пакета (`domain/<пакет>/styleguide_official.json`, иначе `styleguide.yaml`); фото обложек из `domain/<пакет>/photos/photos.json` (класс D, источник и лицензия в подписи); генерации нет |
| `tasks.py` + `prompts/tasks.md` | задания: модель предлагает, код проверяет ключи без модели (утверждения узла со `status: ok`, совпадение с текстом шага, пересчёт расчётных, проверка текста агента A `check_course_items`); не прошедшие — в отчёт, не правятся вручную; прошедшие пишутся в формате `task.schema.json` и проверяются по схеме |
| `llm.py`, `models.yaml` | вызовы модели через кэш и учёт денег агента A; манифест моделей B |
| `static/` | приложение курса: путь, страница шага, задания, карточки, конспект с печатью в PDF, карта связей; без сети |

Повторная сборка без изменений слоя берёт задания из `cache/llm/` и стоит $0. Журнал вызовов — `runs/<глава>/course_llm_calls.jsonl`.

## Интерфейс курса

- Рабочая среда: верхняя панель (глава, прогресс, тема), слева постоянная навигация — разделы приложения, прогресс,
  «Продолжить», дерево разделов и уроков, у текущего урока — его блоки с подсветкой читаемого; на телефоне дерево
  в выдвижном меню, разделы приложения — нижняя панель, у урока липкая полоска «Содержание · 4/15».
- Урок: заголовок для новичка и название книги, метки шага, легенда меток текста; основной поток (суть, понятия,
  механизм, по шагам, примеры, цифры, формулы, таблицы, частая ошибка) → «Проверь себя» → данные, аналогия,
  иллюстрации; справочные блоки (как сейчас, ручной труд, глубже, задачи книги, связи шага, источник) свёрнуты в
  «Справку к шагу». Пустые блоки не показываются.
- Четыре метки текста с иконкой и словом: «по книге, стр. N» (кнопка открывает дословный текст автора), «пояснение
  модели», «гипотеза», «ждёт проверки». Пометки модели в тексте («[гипотеза]») и внутренние ссылки «nNN» сборщик
  превращает в флаг абзаца и в ссылку на шаг.
- Схемы шага — HTML-блоки по спецификации из `illus.py` (текст не мельче 16 px на любой ширине), нейтральная гамма;
  метка происхождения — цветом из стайлгайда; та же схема лежит файлом `illus/*.svg`.
- Фото: только обложка курса, обложки разделов и итоговый экран; полоса над заголовком, метка «фото · атмосфера»,
  подпись с автором, лицензией и ссылкой; файлы и реестр — в доменном пакете (`domain/<пакет>/photos/`). Нет фото
  в пакете — нейтральная обложка без фото.
- Проверено в браузере на 320/390/1280 px в обеих темах: нет горизонтальной прокрутки, текст ≥16 px, нет ошибок
  в консоли, работает по file://.

## Ролики и сцены

### Установка (macOS, Windows, Linux)

```bash
python3 -m venv .venv                      # Windows: py -m venv .venv
.venv/bin/pip install -r requirements.txt  # Windows: .venv\Scripts\pip install -r requirements.txt
```

Ещё нужны два внешних инструмента; оба находятся сами, настраивать пути не надо:

- **FFmpeg** (сборка видео, громкость −16 LUFS): macOS `brew install ffmpeg`, Windows `winget install Gyan.FFmpeg`,
  Linux `sudo apt install ffmpeg`. Ищется в PATH, в Homebrew, winget, Chocolatey, scoop; другой путь — `KMG_FFMPEG_DIR`.
- **Браузер семейства Chromium** (кадры сцены рисует та же страница, что и интерактив курса): подходит установленный
  Google Chrome, Microsoft Edge или Chromium. Если их нет — `.venv/bin/python -m playwright install chromium`.
  Порядок поиска: `KMG_BROWSER` (путь или канал chrome/msedge/chromium) → Chromium Playwright → Chrome → Edge → Chromium.

Голос — онлайн-голоса Microsoft (пакет `edge-tts`, ключ не нужен, наружу уходит только текст сценария).
Проверка готовой дорожки — локальное распознавание речи `faster-whisper` (модель `small` скачивается один раз, ≈0,5 ГБ;
другую задаёт `KMG_ASR_MODEL`); если пакет не установлен, ролик собирается, а в паспорте написано «не выполнялась».
Сценарий пишет модель через общий `kmg.llm` (транспорт из `config/models.yaml`: `claude_code` — подписка Claude Code,
`api` — ключ); принятый сценарий кэшируется, повторная сборка модель не вызывает.

Команды ниже — в виде macOS/Linux (`.venv/bin/python`); в Windows — `.venv\Scripts\python`.

```bash
# ролик по узлу: сценарий → голос → кадры → mp4 + паспорт (код выхода ≠ 0, если паспорт не проходит схему организаторов)
.venv/bin/python -m kmg_course video out/<глава>/layer.json <node_id> --format short|long [--template <id>] [--new-script]
# кадры всех частей сцены без сценария и голоса, $0 — проверить шаблон на узле до того, как платить за сценарий
.venv/bin/python -m kmg_course preview out/<глава>/layer.json <node_id> [--format short|long] [--template <id>]
# отчёт о покрытии шаблонами по видеоёмким узлам (out/<глава>/template_coverage.md/.json) + реестр scenes/registry.json
.venv/bin/python -m kmg_course coverage out/*/layer.json
# после правки факта в слое: одна команда пересобирает ролики главы, чьи факты изменились, и курс (страницы шагов)
.venv/bin/python -m kmg_course refresh out/<глава>/layer.json [--all] [--no-course]
```

Два ролика обучающих глав:

```bash
.venv/bin/python -m kmg_course video out/bas-xxiii/layer.json bas-xxiii.n-475-e20d95 --format short   # шортс 9:16
.venv/bin/python -m kmg_course video out/lat-v/layer.json lat-v.n-092-fe1183 --format long            # разбор 16:9
```

### Правка факта → ролик и страница шага

Слой — единственный источник. Правится утверждение узла в `out/<глава>/layer.json` (или через `overrides/` агента A и
пересборку слоя), затем `refresh`: у каждого ролика главы сравнивается отпечаток фактов узла (проверенные утверждения +
заблуждение) с тем, по которому написан `script.json`; изменился — сценарий пишется заново (один вызов модели), проходит
проверки, голос синтезируется для изменившихся фраз (кэш `cache/tts/`), ролик и паспорт пересобираются; затем
`kmg_course build` собирает курс (страница шага и ролик на ней). Правка шаблона сцены — `refresh --all`: только перерисовка,
сценарий не меняется.

### Как устроено

Шаблон узла выбирается так: шаблон роутера агента A (`format.scene_template`), если его правило применимости
выполняется для узла, иначе первый реализованный шаблон, чьё правило выполняется; тот же выбор делает отчёт покрытия.
Правила — данные в `templates/<id>.json` («applies»: тип трудности, признаки видеоёмкости, таблица признаков,
`terms` — сколько проверенных утверждений узла должны говорить о механизме, `not_terms` — о каком механизме говорить
нельзя, потому что сцена его не рисует). `preview` пишет `NN_<часть>.png`, тексты «что видно» для сценария и
проверку инвариантов в `preview.json`.

`video` → `out/<глава>/media/<узел>/`: `*_short.mp4` (9:16) или `*_long.mp4` (16:9), `scene.html` (интерактив той же сцены
для курса, со своим `voice.mp3`), `subtitles.vtt/.srt` (субтитры вшиты в кадр и дополнительно выгружены файлом для
отключаемого показа), `passport.json` (схема организаторов `passport.schema.json` + поля команды), `passport.html`
(открывается двойным щелчком), `passport.md`, `spec.json`, `timeline.json`, `script.json`.
Следующая сборка курса (`build`) ставит ролик и интерактив на шаг узла (копирует файлы из `manifest.json`).

Конвейер: спецификация сцены из шаблона (`video/templates/<id>.json` + `.js`) → сценарий (модель, роль `script`,
промпт `prompts/script.md`) → проверки без модели (каждая фраза частей reveal/explain/data → утверждения узла `status: ok`,
кроме мест с сомнительным распознаванием из `typos` слоя; фраза ≤18 слов; без формул и греческих букв; on_screen ≤7 слов;
объём под формат; текст не противоречит вычисленной сцене; проверка текста агента A) → голос (онлайн-голоса Microsoft,
словарь ударений и чтений доменного пакета — ударение знаком U+0301, повторы, кэш, один голос на серию, запасной путь) →
таймлайн по меткам слов → инварианты сцены (чек-лист физики) до рендера → кадры той же страницы в браузере → FFmpeg
(−16 LUFS) → распознавание дорожки → паспорт → проверка паспорта по схеме организаторов.

**Легенда — данные доменного пакета, не код.** Цвета пород, флюидов, кривых, измерения, неопределённости и меток
происхождения, фон, шрифт, безопасная зона 9:16 и минимальный размер подписи берутся из
`domain/<пакет>/styleguide_official.json` (стайлгайд организаторов; если в пакете его нет — файл организаторов
`docs/organizers/pack/03_стайлгайд/styleguide.json` и предупреждение). Какой элемент легенды рисует объект сцены, задаёт
шаблон (`legend_keys`, `curve_key` колонок). В коде остались только цвета без предметного смысла (акцент интерфейса,
красный «неверно», сталь обсадной колонны). Глубина растёт вниз; школа ГИС — русская (из стайлгайда).

**На каждом кадре:** метка происхождения ровно «реальные данные» / «симуляция» / «схема» в цвете легенды и пояснение,
плашка «Не в масштабе» с названным преувеличением (число вычисляется из нарисованной геометрии и принятых в шаблоне
размеров `true_scale`), в 9:16 все подписи в безопасной зоне, субтитры не мельче 44 px. В `pressure_diffusion` первый
кадр показывает тот же пласт в истинном масштабе.

**Паспорт:** чек-лист физики отвечается по пунктам доменного пакета: шаблон объявляет, какие пункты его сцена отвечает
и каким инвариантом (`physics` в JSON шаблона; «да» только если инвариант выполнен), условие применимости — по тому,
называет ли голос утверждение-условие узла; остальное «н/п». «Проверить на слух» — слова, которым словарь задал ударение
или чтение.

| Шаблон | Класс кадров | Модель состояния |
|---|---|---|
| `pressure_diffusion` | B | D(x,t) = erfc(x / 2√(κt)) — решение уравнения пьезопроводности: заливка пласта, профиль, граница зоны ∝ √t, датчик |
| `log_panel_decision` | A | синтетическая скважина из таблицы признаков книги: уровни ячеек → кривые; неразличимые по первой кривой пласты и различающие кривые вычисляются |
| `radial_profile` | B | два пласта (вода / нефть) у скважины; сопротивления зон по формуле Арчи, показание зонда — среднее зоны проникновения и пласта с весом J = 1 − exp(−глубина/глубинность); направление проникновения и влияние глубокого проникновения вычисляются. Отношение фильтрат/вода и глубина проникновения выбираются по тексту узла |
| `cutoff_transfer` | B | синтетические интервалы испытаний вокруг связи «кривая → свойство», наименьшие квадраты; критическое значение свойства → граничное значение кривой → разметка пластов «коллектор / неколлектор»; сдвиг порога пересчитывает число коллекторов |
